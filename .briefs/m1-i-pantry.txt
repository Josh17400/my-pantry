## Build

### 1. Pantry list
Grouped by location, searchable, filterable (all / low / out / expiring). Each row shows name,
quantity in **human units** (`formatQuantity` — "2.5 lb", not "1134 g"), status band, and
**provenance** (`✓ receipt · 2 days ago` / `⚠ 3 cooks since verified`).

Must stay responsive at 500 items — virtualize or paginate, and say which in the report.

### 2. Item detail
Quantity with provenance, location, par level, low threshold, expiry, purchase history from
the ledger. Actions:

- **Adjust quantity** — writes a `relative` txn (`adjust_delta`).
- **Recount** — writes an **`absolute`** txn (`targetBase`). This is the "snap to reality"
  flow. It is semantically different from an adjustment and the UI must make that clear:
  a recount says *"there is exactly this much"*, an adjustment says *"add/remove this much."*
- **Mark used up** / **waste** — appropriate txn reasons.
- Edit par level, threshold, expiry, location.

All writes go through `usePantry().appendTxn(...)`.

### 3. Locations
CRUD over user-defined, one-level-nestable locations (Fridge / Pantry / Around the House →
Spices, Tea & Coffee, Baking, Household). Icon and tint per location. **Not an enum** —
the user can add "Garage Freezer" or "Office Drawer".

### 4. Add item
Manual add: search the seeded ingredient catalog, pick form and quantity, choose location.
Writes a `purchase` txn.

## Non-negotiables

- **Never render false precision.** SPEC: a drifted number must look drifted. Provenance is
  displayed everywhere a quantity is.
- **Empty states** — an empty pantry is the default first-run state, not an edge case.
- **Undo.** A mis-tapped deduction must be reversible; the ledger makes this a compensating
  txn. Offer it after destructive-feeling actions.
- Status text uses the `low` token; `low-fill` is bars/dots only (contrast).
- Loading and error states on every async path.
