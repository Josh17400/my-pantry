## Build

### 1. Recipe list
Cards with image placeholder, title, time, servings. Filter by "can make now" using
`findCookableRecipes`. Search by name and by ingredient.

### 2. Recipe detail
Ingredients with **have / need indicators per line**, steps, servings, times. A servings
stepper that live-rescales via `scaleRecipe`. "Add missing to grocery list."

### 3. Recipe create / edit
Title, servings, times, ingredient lines (search the seeded catalog, or free text), steps.
Free-text lines that don't resolve must be marked `unknownAllergens: true` — **treat unknown
as unsafe, never as clear.** This is a safety requirement from SPEC, not a nicety.

### 4. Cook flow — the core interaction

This is `planCook(recipe, servings, pantry)` made visible. **Never a silent subtract.**

**Preview screen** showing, per ingredient: need · have · shortfall · status
(enough / short / not-convertible / missing / optional-missing / non-quantified), plus
`uncertaintyPct` where the conversion is shaky.

The user can then:
- **Edit what they actually used** — real cooking is not exact; this is the main defence
  against drift.
- Mark substitutions.
- Send shortfalls to the grocery list.
- Confirm.

**On confirm:** write all txns under **one `cookEventId`** so the entire meal undoes as a
unit, via `usePantry().appendTxn(...)`.

**Handle these explicitly:**
- **Going negative** → prompt *"still have some?"*. SPEC is explicit: do not silently clamp,
  do not hide a negative. That prompt is how reality gets recovered.
- **Not-convertible lines** → surface plainly; never treat as zero, never guess.
- **Optional lines** never block a cook.
- **Substitution groups** — satisfied if any member is.

### 5. Undo
Immediately after a cook, offer undo. The ledger makes this a compensating entry keyed on
`cookEventId`.

## Non-negotiables

- The deduction preview is **always** shown and **always** editable before commit.
- Allergen-unknown lines are visibly flagged.
- Empty state (no recipes yet) invites creating or browsing.
- Loading and error states everywhere.
