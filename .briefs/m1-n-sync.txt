## What to build

### 1. Auth
Email sign-in/sign-up via Supabase, session persistence, sign-out. A signed-out user must still
have a **fully working local app** — offline-first means auth is optional, not a gate. Do not
put a login wall in front of the pantry.

### 2. Push
Insert local txns not yet acknowledged. `ON CONFLICT (household_id, client_txn_id) DO NOTHING`
— idempotent by construction, so a retry after a dropped connection is free. Mark rows
acknowledged only after the server confirms.

### 3. Pull
Rows where `accepted_at > cursor`, ordered by `accepted_at`, paged. Persist the cursor locally.

### 4. The part that is easy to get wrong

`SYNC.md` spells this out and it is the crux of the track:

> The fold orders by `(occurred_at, device_id, client_txn_id)` — the **client** clock.
> The pull cursor orders by `accepted_at` — the **server** clock.
> **These are different orderings. Arrival order is not fold order.**

So after a pull you may **not** simply append and increment. For each affected ingredient, call
**`needsRefold(watermark, incomingTxn)`** from `@larder/core`; when it returns true, re-fold
that ingredient via `foldLedger`. Both functions already exist — call them.

**Write a test for exactly this**: pull a txn whose `occurred_at` sorts *before* the local
watermark and assert the projection matches a full re-fold. That is the bug this track exists
to prevent, and it only ever appears on a second device.

### 5. Metadata sync
Recipes, par levels, locations: last-write-wins on `updated_at`. Only the ledger needs union
semantics.

### 6. Conflict surfacing
When `foldLedger` reports `conflict: true` (two concurrent recounts), surface it **once** —
don't spam, don't hide it. The fold already detects this; you just need to route it.

### 7. Sync UX
Background sync on app focus and after local writes. Visible state: synced / syncing / offline
/ error. **Never block the UI on the network** — the grocery store is the offline case and it
is the whole point.
