**The Good Pantry.** Read `SPEC.md` and `DESIGN.md`, and **look at the mockups**:
`design/references/mockup-01-overview.jpg`, `mockup-02-home-stats.jpg`, `mockup-03-greeting.jpg`.
This screen is the one all three mockups depict — match them.

Everything you need already exists:

  FreshnessBar, ItemTile, PlaceholderThumb, AdSlot, Fab, TabBar, Wordmark. See `/design`.

**Do NOT edit** `App.tsx` (the architect wires routing), `src/ui/**`, `src/state/**`,

## Build

Per the mockups, top to bottom:

1. **Header** — Wordmark + greeting ("Good morning, Alex" — time-of-day aware), search affordance.
2. **At a Glance** — location summary cards (Fridge / Pantry / Around the House / Favorites)
   with item counts and a status word. Counts come from `usePantry()` + `useLocations()`.
3. **Cook-now banner** — *"Make something amazing — you have everything for 6 recipes."*
   Use `findCookableRecipes` from `@larder/core`. **This is free-tier core logic, NOT AI.**
4. **Recipe Inspiration** — a Rail of recipes, prioritising ones that **use up expiring
   ingredients** ("Use up: spinach, garlic, parmesan"). The expiry-driven ordering is a
   first-class requirement from the designs, not a nicety.
5. **Fridge Highlights / Pantry Staples** — Rails of ItemTiles showing quantity **and
   provenance/status** (`6 left · 2 days`, `Almost empty`, `Plenty`).
6. **AdSlot** — in-feed, well clear of the tab bar (AdMob placement policy). Free tier only.

### Non-negotiables

- **Provenance is visible.** SPEC requires every quantity carry its confidence — a drifted
  number must look drifted. Use the provenance fields; do not render bare confident numbers.
- **Empty state.** A new user has an empty pantry — that is the default, not an edge case.
  Design a genuine first-run state that invites adding items. Never render a broken-looking
  screen full of zeros.
- **Loading and error states** for every async read.
- Use the `low` token for status *text* and `low-fill` only for bars/dots — the vibrant amber
  fails contrast as text.

## Constraints

- Mobile-first, 44px minimum tap targets, safe-area aware.
- No new dependencies. No product logic that belongs in `@larder/core` — if something is
  missing there, note it in the report rather than writing it here.
- Create no git commits.
