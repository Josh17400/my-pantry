## Task 1 — close the gluten gap FIRST, before any chef work

The seed track made a defensible call and flagged it honestly: **barley is untagged** because
it contains gluten but is not a FALCPA "wheat" allergen. That is technically correct and
practically dangerous — gluten is precisely what a celiac user needs to avoid, and this track
is about to ship something that recommends food to people.

Add a **dietary-flag axis separate from the FALCPA allergen list**:

```ts
type DietaryFlag = 'gluten' | 'pork' | 'alcohol' | 'beef' | 'shellfish-derived' | ...
```

- Tag gluten-containing grains: wheat, barley, rye, spelt, farro, malt, brewer's yeast,
  conventional oats (cross-contamination — flag with a note), soy sauce (contains wheat).
- Keep `Allergen` as the regulatory list; `DietaryFlag` is the practical one. Do not conflate
  them — they answer different questions.
- Extend `allergensDisagree` / `canAutoMergeAllergens` (or add siblings) so matching refuses to
  auto-merge across disagreeing dietary flags too.
- Add tests. Barley must be gluten-flagged. A gluten-free user must never be auto-matched into
  a gluten-containing ingredient.

**Report what you tagged and what you were unsure about.** Under-tagging is a safety failure;
over-tagging is merely annoying.

## Task 2 — the chef Edge Function

`supabase/functions/chef/` mirroring the parse-receipt structure.

- Auth required. **Entitlement-gated** — paid tier only. Free users get a clear upsell, never a
  broken screen.
- **Dollar-denominated budget per user per month**, not a message count. Same reasoning as
  receipts: one user with a script must not run up an unbounded bill.
- Rate limit per user.
- Context: pantry snapshot, dietary profile (allergens **and** the new dietary flags), and the
  current recipe when relevant.
- `OPENROUTER_API_KEY` from function secrets only. Never in the client, never `VITE_`-prefixed.
- Cheap Flash-class model for chat and substitutions; step up only for recipe generation.

### The hard allergen gate — non-negotiable

- The chef **may not** recommend anything containing a flagged allergen or dietary flag.
- Free-text recipe lines that did not resolve carry `unknownAllergens: true` — **treat unknown
  as unsafe, never as clear.**
- Filter server-side, after the model responds. **A prompt instruction is not a safety
  control** — models do not reliably obey, and this is the one place that matters. Enforce it
  in code, and test that a model response containing a flagged ingredient is blocked.

### Capabilities
"What can I make tonight" (grounded in the real pantry, not invented), substitutions with
ratios, guided cooking Q&A, and recipe generation that saves as a **real `Recipe` with mapped
ingredients** so it can be cooked and deducted like any other.
