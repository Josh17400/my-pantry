# BRIEF: Re-platform the app shell — Expo → React + Vite + Capacitor

## Why (read this, it prevents wrong assumptions)

The owner has a **proven, debugged, Mac-free iOS pipeline** already shipping another app:
Capacitor → GitHub Actions (`macos-26`) → fastlane → cloud signing via App Store Connect API
key → TestFlight. Expo Go for SDK 57 is not on the App Store yet, which blocked device
verification entirely, and standing up EAS would mean maintaining a second mobile pipeline.

So we are switching the **shell only**. This is not a rewrite.

## The single most important constraint

> **`packages/core` IS NOT TO BE TOUCHED.** It contains 248 passing tests across 28 files —
> the unit conversion graph, the two-kind ledger fold, par levels, provenance, matching with
> allergen guards, de-duplication, recipes, grocery, and ~300 seeded ingredients. It is pure,
> framework-agnostic TypeScript with zero React and zero platform APIs, which is exactly why
> this migration is cheap.
>
> If you find yourself editing `packages/core`, stop — you have misunderstood the task.
> The **only** permitted exception is `packages/core/src/sqlite-health.ts` if the health DDL
> genuinely needs to move; justify it loudly in the report if so.

`npm run test` must still report **248 passing** (plus any new shell tests) when you are done.

## Stack

- **React 19 + Vite + TypeScript strict**
- **Tailwind CSS** — the design system in `DESIGN.md` is written for it, and NativeWind was
  Tailwind-flavored anyway, so this is a simplification not a change
- **Capacitor 8.x**, matching euchre-game's versions
- **Drizzle** over `@capacitor-community/sqlite`. Drizzle has no official Capacitor driver —
  use `drizzle-orm/sqlite-proxy`, which takes an async executor callback and fits the
  Capacitor SQLite API cleanly. If you find a better-supported route, take it and justify it.
- Keep `@supabase/supabase-js`. Keep the existing `.env` contract
  (`EXPO_PUBLIC_*` names must be renamed to Vite's `VITE_*` convention — **the `.env` file at
  `apps/mobile/.env` has real credentials in it; carry the values over, do not lose them, and
  do not print them**).

## The web dev-loop question — resolve with evidence, do not guess

Web is an **online companion** (no local SQLite) — that decision stands. But the owner's dev
loop is browser-first, and developing offline-first native code without a browser path is slow.

`@capacitor-community/sqlite` ships a `jeep-sqlite` wasm web implementation intended for
development. **Investigate whether it works without COOP/COEP headers** (that requirement is
what killed the Expo web path — see `SPEC.md`). If it works cleanly, wire it as a
**development-only** driver so the DB can be exercised in the browser. If it needs the same
origin-wide headers, do not use it — report that and leave web on Supabase-direct.

Report what you actually found, with evidence. This is the single highest-value unknown here.
